강철제국 리워크 v0.8.1 — 미진행 이벤트 조건 무시 예약
작성일: 2026-10-14

1. 사용 순서
월드맵 또는 도시의 기본 화면에서 F8을 누릅니다.
원하는 사건 → 발동 조건과 강제 설정 → 조건 무시 예약 켜기를 선택합니다.
창을 닫고 해당 사건이 원래 시작되는 도시·건물을 방문하거나 월드맵으로 나갑니다.
해당 사건의 최초 발동 판정에 도달하면 조건을 무시하고 원본 사건이 시작됩니다.
이미 그 장소에 있다면 나갔다 다시 들어가세요. 메뉴에서 즉시 장면으로 이동시키지는 않습니다.
예약 취소는 같은 메뉴의 조건 무시 예약 끄기를 선택합니다.

2. 바뀌는 조건
레벨, 부채, 경과 연도, 동료 수, 군단 수, 기존 분기 때문에 막히는 최초 발동 조건을 우회합니다.
예: 라이벌을 끝낸 뒤에도 아직 한 번도 시작하지 않은 고대인의유적 사건을 예약할 수 있습니다.
다른 사건의 완료 기록을 0으로 초기화하거나 기존 선택 기록을 덮어쓰지 않습니다.
같은 사건을 시작·거절·실패·완료한 기록이 있으면 예약할 수 없습니다.
이미 진행 중인 사건을 처음부터 다시 시작할 수도 없습니다.
원본에서 거절과 완료를 같은 값으로 기록한 사건은 둘 다 재실행이 차단됩니다.

3. 진행 중 사건과 여러 예약
다른 주요 사건이 진행 중(STS_EVENT가 0이 아님)이면 강제 발동은 대기합니다.
현재 사건을 정리한 후 예약한 사건의 발동 장소를 다시 방문하세요.
여러 사건을 예약할 수 있지만 실제 시작 순서는 원본 스크립트 실행 순서와 방문 장소에 따릅니다.
최초 발동 시 해당 예약은 자동으로 꺼집니다. 시작 전에는 언제든 취소할 수 있습니다.
예약은 일반 게임 저장에 포함됩니다. 저장하지 않고 종료하면 최근 저장 이후 변경은 사라집니다.
새 게임에서는 모든 예약이 꺼집니다. 기존 저장에서는 기본적으로 꺼진 상태입니다.

4. 사건별 원래 발동 장소
시작과 상속: 새 게임의 동방제국 시작 장면. 일반 플레이에서는 이미 시작한 사건이므로 잠깁니다.
주디스: 월드맵 일반 이벤트 처리 시점. 월드맵으로 나가세요.
라이벌: 베브 주점.
인도하는자: 포룸 주점.
밀로셰비치대령: 사키로 총포상점.
그락쿠스형제: 카란토 도시 진입.
고대인의유적: 포룸 도시 진입.
깽디쉬박사: 샤르데나 주점.
최후의결전: 포룸 도시 진입.

5. 적용 범위
F8에 표시되는 주요 사건 9개의 최초 시작에 적용됩니다. 일반 도시 의뢰는 대상이 아닙니다.
사건 시작 이후의 전투·퍼즐·아이템 전달·이동·후속 단계 조건과 선택 결과는 원본대로 진행됩니다.
최후의결전을 강제로 시작하면 원본의 후속 시간 제한과 엔딩 흐름도 시작됩니다.
본대 주둔과 동료 유무도 최초 판정에서는 우회하지만, 후속 장면에서 본대나 동료가 필요할 수 있습니다.
원래 배타적인 분기를 함께 진행한 경우 후속 스토리 조합 전체의 정상 완주는 보장하지 않습니다.
원본 후속 장면이 주는 보상·병력 생성·장면 전환은 그대로 실행됩니다.
이미 진행한 사건을 복원하려고 이전 저장을 불러오면 그 저장에 기록된 진행 상태가 기준입니다.

6. 저장 및 설치
원본의 100개 전역 값 저장 영역 중 스크립트가 쓰지 않는 98·99번 칸에 식별자와 예약 비트를 보관합니다.
기존 사건 값 0~30은 설정 메뉴에서 수정하지 않습니다. 저장 파일 길이와 배치는 바뀌지 않습니다.
설치 프로그램은 현재 v0.8.0 실행 파일을 확인하고 백업한 뒤 SteelEmpire.exe만 교체합니다.
저장 파일, 인물 에디터, QHD/16:9 런처, 화면 설정, 기존 데이터 패치는 교체하지 않습니다.
복원은 새 백업 폴더의 Restore.ps1을 이용합니다. 실행 파일 복원은 이미 진행한 저장을 되돌리지는 않습니다.

7. 검증
원본 78개 스크립트의 조건 판정 233개를 이전 실행 파일과 비교했습니다.
설정이 꺼졌을 때 기존 판정 유지, 예약 시 지정한 9개 시작 판정만 변경되는 것을 확인했습니다.
진행 값·동시 진행 여부·설정 조합 486개, 재실행 차단 54개와 메뉴 켜기/끄기를 검증했습니다.
원본 시작 단계 대입, 새 게임 초기화, 원본 저장/불러오기 함수의 예약 값 보존을 검증했습니다.
기존 이벤트 창 표시, 전투, 재훈련 UI, 경험치 재분배 회귀 검사를 실행했습니다.
검증은 코드 비교와 기계어 에뮬레이션입니다. 실제 게임에서 모든 분기를 완주한 검증은 아닙니다.
