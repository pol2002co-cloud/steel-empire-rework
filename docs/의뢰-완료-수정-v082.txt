강철제국 리워크 v0.8.2 — 의뢰 보상 수령 후 목록 잔류 수정

원인
원본 의뢰 삭제 함수는 전달받은 의뢰 자체가 아니라 종류와 목적지가 같은 첫 번째 의뢰를 삭제했습니다.
운송 의뢰가 겹치면 보상을 받은 의뢰가 남고 다른 의뢰가 없어질 수 있습니다.
원본 실행 파일로 동일 목적지 의뢰 두 개를 구성하여 잘못된 삭제를 재현했습니다.

수정
보상 지급, 기간 만료, 스크립트의 의뢰 삭제 요청에서 실제 대상 의뢰만 삭제합니다.
보상 금액, 아이템 인도, 도시 평판 증가 규칙은 유지합니다.
새 수정은 앞으로의 잘못된 삭제를 방지하며 이미 잘못 저장된 의뢰를 추정해서 일괄 삭제하지 않습니다.

개별 저장 복구
사용자가 지급 완료를 확인한 첫 번째 슬롯 Steel0.Sav의 보석지팡이 의뢰 한 건만 복구 대상으로 지정했습니다.
조건: 완료 상태 3, 운송 유형 1, 의뢰 세력 17, 출발 도시 68, 목적 도시 47, 아이템 73, 보상 5,040,000.
복구는 해당 300바이트 의뢰 기록과 의뢰 개수만 정리합니다. 소지금은 수정하거나 보상을 재지급하지 않습니다.
다른 저장 슬롯은 수정하지 않습니다. 기존에 잘못 지워진 의뢰는 확실한 복원 근거가 없어 새로 만들지 않습니다.
실행 파일과 저장 파일은 각각 별도로 백업합니다. 원래 저장 복원은 게임을 종료한 뒤 백업 Steel0.Sav를 복사합니다.

검증
개별 의뢰 삭제·빈 목록·없는 대상·양방향 목록 연결·레지스터 보존 35개 사례 통과.
원본의 잘못된 삭제 및 수정 후 정상 삭제를 실제 보상 처리 기계어 경로에서 재현/비교.
기존 v0.8.1의 코드 변경 범위는 의뢰 삭제 함수 8바이트와 추가 코드 영역으로 한정.
이벤트 창 97개 표시 사례, 강제 발동 486개 조합, 원본 조건 233개, 저장/불러오기 검사 통과.
실제 게임에서 의뢰 완료 플레이를 다시 실행한 검증은 하지 않았습니다.
