강철제국 리워크 v0.8.3 — 다른 PC에서 대화·선택창 한글이 깨지는 문제 수정

원인
게임의 UI 리소스 문자열은 UTF-16으로 저장되어 있습니다.
원본 UI 문자열 읽기 함수는 WideCharToMultiByte에 코드페이지 0(CP_ACP)을 전달합니다.
이 값은 Windows의 비유니코드 프로그램 언어 및 UTF-8 옵션에 따라 달라집니다.
게임의 비트맵 글꼴은 CP949 바이트를 기대합니다. 서유럽 코드페이지에서는 한글이 ?로 대체되고,
UTF-8 코드페이지에서는 3바이트 한글 때문에 원본이 확보한 2바이트 기준 버퍼가 부족해 변환이 실패할 수 있습니다.
변환 실패를 확인하지 않으므로 이전 버퍼 내용이나 맞지 않는 바이트가 표시될 수 있습니다.
이에 따라 일부 고정 설명은 정상이면서 리소스 기반 대화·선택창 글자만 깨지는 현상이 가능합니다.

수정
UI 문자열 변환 경로의 코드페이지를 CP949(949)로 고정했습니다.
Windows 시스템 로캘, 레지스트리, UTF-8 베타 옵션이나 글꼴 설치를 변경하지 않습니다.
기존 CP949 환경의 출력과 동일한 바이트를 유지합니다. 저장 데이터와 전투·이벤트 규칙은 변경하지 않습니다.

기존 v0.8.2 사용자가 있는 경우: v0.8.3 Update ZIP을 별도 폴더에 풀고 Install-Update.ps1에 게임 폴더를 지정합니다.
예: powershell -NoProfile -ExecutionPolicy Bypass -File .\Install-Update.ps1 -GamePath "D:\Games\SteelEmpire-Rework"
게임과 런처·에디터를 종료한 뒤 설치하세요. 프로그램을 백업하며 저장 파일과 기존 ddraw.ini는 유지합니다.
이전 v0.8.2 전체본에 v0.8.3 업데이트를 적용해도 같은 최신 실행 파일이 됩니다.

검증
실제 UI 리소스와 경계값을 포함한 102개 문자열을 코드페이지 949/1252/65001에서 검사했습니다.
기존 코드의 출력 불일치 192건을 재현했고 수정 후 동일한 CP949 출력, 버퍼 경계, 입력 포인터 이동과 호출 규약을 검증했습니다.
실제 32비트 Windows 프로세스의 ACP를 UTF-8(65001)로 지정한 검사에서도 원본 CP_ACP 변환 실패와 CP949 고정 변환 성공을 확인했습니다.
이벤트 진행창·강제 예약·의뢰 삭제·재훈련 UI 회귀 검사를 통과했습니다.
수정된 코드 범위는 UI 문자열 변환 한 곳 10바이트와 추가 명령 영역입니다.
문제가 발생한 제보자의 PC에서 수정 후 화면을 직접 확인한 검증은 아직 별도입니다.
